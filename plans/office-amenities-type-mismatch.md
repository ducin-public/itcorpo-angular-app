# Office amenities type mismatch

## Problem summary

Angular template compilation error:

✘ [ERROR] NG2: Type 'string[]' is not assignable to type 'OfficeAmenity[]'. [plugin angular-compiler]

Occurs in `src/app/offices/office-details/office-details.component.html` at the binding:

    <itcorpo-amenity-list [amenities]="office.amenities"></itcorpo-amenity-list>

The `itcorpo-amenity-list` component expects an input of type `OfficeAmenity[]`, but `Office.amenities` is currently typed as `string[]` in the autogenerated `data-contracts.ts`.

## Root cause analysis

- The TypeScript definitions in `src/app/api/data-contracts.ts` (generated by swagger-typescript-api) define two different shapes for office-like types:
  - `Office` has `amenities: string[]`.
  - `OfficeInput` has `amenities: OfficeAmenity[]`.
- The components in the UI expect `OfficeAmenity[]` (see `amenity-list.component.ts` which imports `OfficeAmenity` and declares `@Input() amenities!: OfficeAmenity[];`).
- When components receive an `Office` instance (for example from `OfficesService.getAllOffices()` which returns `Office[]`), `office.amenities` is typed as `string[]`, causing a type mismatch at template compile-time.

Why generation differs:
- The API generator often models the server's read model and write model differently. The server's GET /offices may return only amenity codes (string[]), while POST/PUT expects full objects (OfficeAmenity[]). The UI currently assumes the read model contains full objects.
